# ご意見フォームの設計

Webサイトの利用者から、レシピを使った結果や困ったこと、新しいレシピの要望を受け取るためのフォーム。利用者にGitHubのIssueを書いてもらうことは想定しない（[distribution.md](distribution.md) の「フィードバック」）。βの段階では Google フォームで作る。

## 目的

- **レシピの改善**：どのレシピの、どの手順で、何に困ったかを知る
- **評価の補完**：テストセットでは分からない、実際の業務での結果（そのまま使えたか、どれだけ直したか）を集める。[evaluation.md](evaluation.md) の評価項目と比べられる形で聞く
- **利用環境の把握**：どのAIサービスで使われているか、文字数の上限で困っていないかを知る
- **次のレシピの候補を集める**：どんな業務でAIを使いたいか、今のレシピで足りないものは何かを知る

## 方針

- **個人情報を集めない**。メールアドレスは収集せず、名前や所属の名前も聞かない
- **資料やAIの出力の中身を書かせない**。自由記述の欄に会議の内容や規約の文などを貼られると、フォームに機密情報がたまる。注意書きを、フォームの説明と自由記述の欄の両方に置く
- **選んで答える質問を中心にする**。AIに不慣れな人でも1〜2分で答えられ、集計しやすい
- **ログインを求めない**。組織のネットワークや端末では、Googleアカウントにログインできないことがある

## フォームの説明文

タイトルは「AI業務レシピ　ご意見・レシピの要望」。

```text
AI業務レシピを使っていただき、ありがとうございます。
使ってみた結果や困ったこと、「こんなレシピがあったら使いたい」というご要望をお聞かせください。
1〜2分で終わります。

レシピを使っていない方は、ご感想やご要望だけでも大丈夫です。
  ・お名前やメールアドレスはお聞きしません。
  ・資料（会議の文字起こし、規約の文など）やAIの出力の中身は、書かないでください。
  ・いただいたご意見は、レシピの改善に使います。個別の返信はしていません。
```

送信後のメッセージは「ご回答いただきありがとうございました。今後の参考にさせていただきます。」。

## 質問

| # | 質問 | 形式 | 必須 | 選択肢・補足 |
|---|---|---|:---:|---|
| 1 | どのレシピについてのご意見ですか。 | 記述式（短文） | | 説明：「自動で入っている場合はそのままにしておいてください。（レシピのページから開くと自動入力されます）」 |
| 2 | 使っているAIのサービスを教えてください。 | ラジオボタン | ✓ | ChatGPT／Microsoft Copilot／Gemini／Claude／組織で用意されたAIチャット／分からない・まだ使ったことがない／その他 |
| 3 | 使っているAIのモデル名を教えてください。 | 記述式（短文） | | 説明：「GPT-4.1、Gemini2.5 flashなど、今回利用したもの、よく使うもの、分からなければ空欄でも構いません。」 |
| 4 | 使ってみての結果はどうでしたか。 | ラジオボタン | | そのまま使えた／少し修正して使えた／大きく修正して使えた／使えなかった／途中でやめた |
| 5 | 最後まで実施するのに、どれだけ時間がかかりましたか。 | ラジオボタン | | 5分未満／5分〜10分／10〜30分／30分以上 |
| 6 | 使ってみて困ったことがあれば教えてください。 | チェックボックス | | 長すぎて送れなかった／手順が分かりにくかった／AIからの質問が分かりにくかった／AIの出力に間違いがあった／AIの出力に抜けがあった／特に困ったことはなかった／その他 |
| 7 | ご意見・気づいたことがあれば教えてください。 | 記述式（段落） | | 説明：「資料やAIの出力の中身、個人や組織の名前は書かないでください。」 |
| 8 | こんなレシピがあったら使いたいというものがあればぜひアイデアをください。 | 記述式（段落） | | 説明：「AIに手伝ってもらいたい仕事を短く書いてください。例：『アンケートの自由記述をまとめたい』『説明会の想定問答を作りたい』。資料の中身や、個人や組織の名前は書かないでください。」 |
| 9 | お使いの方の職場を教えてください。 | ラジオボタン | | 自治体／企業／地域団体・NPO／学校／個人／その他 |

ご意見フォームと要望の受け付けは、1つのフォームにまとめる。フォームが2つあると、利用者がどちらに書けばよいか迷うためである。そのかわり、要望だけを送る人が答えられなくならないよう、必須は質問2だけにし、選択肢に「分からない・まだ使ったことがない」を入れている。質問2は、どのAIサービスで使われているかを知るために必ず答えてもらう。

質問1を選択式にせず記述式にしているのは、レシピが増えたときにフォームを直さなくて済むようにするため。サイトの各レシピのページから開くと、この欄にレシピ名が自動で入る（次の「サイトとの連携」）。

質問4は、テストの記録の「修正時間」や採点と対応させるための質問。「少し修正して」「大きく修正して」の線引きは利用者の感覚に任せ、細かい定義はしない。質問4・5は集計しやすいよう、「その他」を置かない。

質問8は、業務の名前を短く書いてもらう。「どんな資料を、どうしたいか」が分かれば十分で、資料そのものは求めない。

## フォームの設定

| 設定 | 値 | 理由 |
|---|---|---|
| メールアドレスを収集する | オフ（収集しない） | 個人情報を集めない |
| 回答を1回に制限する | オフ | オンにするとGoogleアカウントへのログインが必要になる |
| 回答者が送信後に編集できる | オフ | 不要 |
| 結果の概要を表示する | オフ | 他の人の自由記述が見えないようにする |
| 回答の保存先 | フォームの「回答」。必要ならスプレッドシートにリンク | スプレッドシートの共有範囲は、運営する人だけに限る |

## サイトとの連携

現在のフォームは、`site/src/site.config.ts` に設定済み（質問1の項目IDは `entry.624644269`）。質問の文言や選択肢を直しても、項目IDは変わらない。質問1を削除して作り直した場合は、項目IDを調べ直す。

1. フォームを作ったら、右上の「送信」→ リンクのアイコンで、回答用のURL（`https://docs.google.com/forms/d/e/.../viewform`）をコピーする
2. 質問1の項目IDを調べる。フォームの右上の「︙」→「事前入力したURLを取得」で、質問1に `テスト` と入れて「リンクを取得」を押す。コピーされたURLに含まれる `entry.数字=テスト` の `entry.数字` の部分が項目ID
3. `site/src/site.config.ts` に設定する

```ts
feedbackUrl: 'https://docs.google.com/forms/d/e/.../viewform',
feedbackRecipeEntry: 'entry.1234567890',
```

設定すると、サイトに次のリンクが出る。

| 場所 | リンク |
|---|---|
| 左メニューの「このサイトについて」 | ご意見・レシピの要望（レシピ名は入らない） |
| 各レシピのページの下部 | 「使ってみて、うまくいかなかったことや気づいたこと、ほかにあったら良いレシピがあれば、ご意見フォームからお知らせください。資料やAIの出力の中身は書かないでください。」（レシピ名が入った状態で開く） |

`feedbackRecipeEntry` を設定しない場合も、リンクは出る。その場合は、レシピ名は入らない。

## 運用

- 回答は、月に1回程度まとめて読み、質問2以外が空の回答を除いたうえで、レシピごとに「結果」と「困ったこと」を集計する
- 質問8の要望は、似たものをまとめて、次に作るレシピの候補の一覧にする。多く寄せられた業務や、既存のレシピの組み合わせで対応できない業務を優先する
- 改善につながった意見は、各レシピの `README.md` の改訂履歴に「利用者の意見を反映」として理由を書く（回答の文はそのまま転記しない）
- 自由記述に資料の中身や個人情報が書かれていた場合は、その回答を削除する

## 注意

- Google フォームは、組織のネットワークによっては開けないことがある。公開後、自治体や企業のネットワークから開けるかを、サイトと一緒に確認する（[distribution.md](distribution.md) の「利用者のネットワーク環境」）
- 開けない利用者が多い場合は、別の受け付け方法（メールアドレスの掲示など）を検討する
