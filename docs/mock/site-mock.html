Meeting · 会議

文字起こしから議事録を作る

会議の文字起こしを貼るだけで、決定事項・ToDo・持ち越し事項が整理された議事録を作ります。

TIME
約3〜5分目標・未実測
LEVEL
★★★AIの知識は不要
STEPS
3ステップ質問がなければ2
MIN. MODEL
GPT-4.1未検証

用意するもの：会議の文字起こし、組織で利用が認められているチャット型のAI

使う前に　次の情報は入力しないでください。
  • 組織の規定でAIへの入力が認められていない会議の内容
  • 不要な個人情報（連絡先、健康や人事評価に関する発言など）。必要なときは「Aさん」「B社」のように置き換えてください

    あなたは、会議の文字起こしから正確な議事録を作成する担当者です。

# 最重要原則

文字起こしに記録されている内容を事実の根拠としてください。

文字起こしにない事実を推測して追加しないでください。
特に、決定事項・担当者・期限・数値・固有名詞を推測で確定してはいけません。

「発言されたこと」と「会議として決まったこと」は別です。
意見や提案があっただけの場合は、決定事項として扱わないでください。


# 処理手順

必ず次の順番で処理してください。

## 1. 抽出

文字起こし全体を確認し、議事録に必要な情報を抽出してください。

以下は整理・除外して構いません。

- 「えー」「あのー」などのフィラー
- 意味のない相づち
- 同じ内容の重複
- 明らかな言い直し
- 議事録に不要な雑談

ただし、発言の意味や結論を変えてはいけません。


## 2. 判定

抽出した内容を、次の基準で判定してください。

【議論・意見】
会議中に出された説明、意見、質問、提案など。

【結論】
その議題について、最終的にどのような状態になったか。
途中で結論が変わった場合は、最後の結論を採用してください。

【決定事項】
会議として明確に合意・確定したこと。
単なる意見、提案、検討案は含めません。

【ToDo】
会議後に誰かが実行・確認・対応すること。
「担当者」「内容」「期限」をそれぞれ確認してください。

【持ち越し事項】
結論が出ていないこと、継続検討となったこと、
次回以降に判断・確認すること。


## 3. 整理

以下の形式で必ず整理してください。

# 会議情報
- 会議名：
- 日時：
- 参加者：

文字起こしから確認できない項目は「不明」としてください。

# 議題と議論

## 議題1：〇〇
- 主な議論：
- 主な意見・提案：
- 結論：

## 議題2：〇〇
- 主な議論：
- 主な意見・提案：
- 結論：

議題数に応じて増減してください。

# 決定事項
-
-

明確な決定事項がない場合は「なし」としてください。

# ToDo

| 担当者 | 内容 | 期限 |
|---|---|---|
| | | |

不明な項目は「不明」としてください。
推測で補完しないでください。

# 持ち越し事項
-
-

ない場合は「なし」としてください。

# その他の重要事項
-

上記に分類できないものの、議事録に残す価値がある重要事項のみ記載してください。


## 4. 確認

最後に、上記の整理結果を確認してください。

正確な議事録を作るうえで重要な情報が不足・曖昧で、
利用者に確認することで議事録の正確性が大きく向上する場合だけ、
質問してください。

質問する必要がない細かな情報については質問しないでください。

特に確認対象となり得るのは以下です。

- 決定したのか、単なる提案なのか判断できない
- 重要なToDoの担当者が分からない
- 重要なToDoの期限が分からない
- 固有名詞の誤変換が疑われ、意味が変わる可能性がある
- 誰の発言かによって意味が大きく変わる

質問が必要な場合は、

# 確認したいこと

1. ○○について、〜でしょうか？
2. ○○について、〜でしょうか？

のように、短く回答できる形で質問してください。
候補が絞れる場合は、「A：〜　B：〜」のように選択肢を添えてください。

重要な確認事項がない場合は、

# 確認したいこと
重要な確認事項はありません。

としてください。


# 禁止事項

以下は行わないでください。

- 文字起こしにない情報の創作
- 文脈だけを根拠とした担当者・期限の確定
- 提案を決定事項に変更すること
- 未決定事項を決定済みとして扱うこと
- 発言者の意図を変えること
- 不明な固有名詞を勝手に修正すること
- 議事録の見栄えを良くするための事実の補完
- 不要な質問を大量にすること

この段階では完成版の議事録を作成しないでください。

# 目的

会議に参加していない人が読んでも、

「何について話し合ったのか」
「どのような議論があったのか」
「何が決まったのか」
「次に誰が何をするのか」

を短時間で理解できる議事録にしてください。


# 出力形式

## 1. 会議概要

- 会議名：
- 日時：
- 参加者：


## 2. 議題ごとの要点

議題ごとに整理してください。

### 議題1：〇〇

**主な議論**
-

**結論**
-

必要に応じて議題を追加してください。

議論の経緯をすべて再現する必要はありません。
結論を理解するために必要な意見・論点を中心に簡潔にまとめてください。


## 3. 決定事項

会議で明確に合意・確定したことだけを箇条書きにしてください。

-

決定事項がない場合は「なし」としてください。


## 4. ToDo・ネクストアクション

| 担当者 | 内容 | 期限 |
|---|---|---|
| | | |

担当者または期限が確認できていない場合は「要確認」としてください。

ToDoがない場合は「なし」としてください。


## 5. 次回への持ち越し事項

結論が出なかったこと、
継続検討すること、
次回以降に確認・判断することを記載してください。

-

ない場合は「なし」としてください。


## 6. 要確認事項

議事録完成時点でも確認できていない重要事項だけを記載してください。

-

要確認事項がない場合、この項目自体を省略してください。


# 編集ルール

- 読みやすく、簡潔な文章にしてください。
- 発言を時系列にそのまま並べるのではなく、議題単位で整理してください。
- 発言者の意図やニュアンスを変えないでください。
- 同じ内容を不必要に繰り返さないでください。
- 意見や提案を決定事項に変更しないでください。
- 決定事項とToDoを混同しないでください。
- 未確定事項を確定表現に変更しないでください。
- 私が追加回答した情報は、文字起こしより新しい補足情報として反映してください。
- STEP 1および私の回答にない事実を新たに作らないでください。


# 最終確認

出力する前に、完成した議事録を確認してください。

次の5点を確認し、問題があれば修正してから出力してください。

1. 推測によって追加した事実がないか
2. 意見・提案を決定事項として記載していないか
3. 決定事項とToDoを混同していないか
4. 重要な決定事項・ToDo・持ち越し事項が抜けていないか
5. 担当者や期限が不明なのに確定した表現にしていないか

確認作業そのものは出力せず、
確認後の完成版議事録だけを出力してください。

    会議概要、議題ごとの要点、決定事項、ToDo、持ち越し事項がまとまった議事録が返ってきます。

長すぎて送れないとき

AIのサービスによっては、1回に送れる文字数に上限があります。次の順に試してください。

  1. プロンプトと文字起こしを分けて送るSTEP 1のプロンプトを、文字起こしを貼らずにそのまま送ります。「文字起こしを貼り付けてください」と返ってきたら、次のメッセージで文字起こしだけを送ります。
  2. 文字起こしも何回かに分けて送るプロンプトを送ったあと、まず次のメッセージを送り、続けて文字起こしを区切って送ります。最後に「以上です」と送ります。
    分割送信の定型文
    文字起こしが長いため、何回かに分けて送ります。
「以上です」と送るまでは処理を始めず、「受け取りました」とだけ返答してください。
「以上です」を受け取ったら、すべての文字起こしをつなげて、最初の指示どおりに処理してください。

  3. 会議を区切って使うそれでも難しいときは、議題ごと、または前半・後半に分けて、それぞれでこのレシピを使ってください。

0 / 5 確認済み

なぜこのプロンプトでうまくいくの？

「この文字起こしから議事録を作って」と一度に頼むと、AIは「重要な情報を探す」「意見と決定を見分ける」「担当者と期限を判断する」「読みやすく書く」といった多くの仕事を同時にこなす必要があります。そのとき、分からない部分を自然な文章で補ってしまい、誤りに気づきにくくなります。

STEP 1 情報を探して分類する（まだ文章にしない） ↓ STEP 2 AIだけで判断できない重要なことだけ質問する ↓ STEP 3 整理済みの情報だけで議事録に仕上げる

特に大事なのは、次の区別です。プロンプトでは、これらの意味をAIに具体的に伝えています。

発言の例扱い
「来月から始めた方がいいと思います」意見・提案
「では来月1日から開始します」決定事項
「田中さん、今月末までにマニュアルを作成してください」ToDo

話者が分からない文字起こしや、「例の件」のような指示語が多い会議は苦手です。最後の確認だけは、人の目で行ってください。

Guide

はじめての方へ

AI業務レシピは、AIに詳しくなくても、普段の仕事を短時間で終わらせるための手順集です。どのレシピも、基本の操作は同じです。

  • 01貼る

    プロンプトをコピーして、資料と一緒にAIへ送ります。

  • 02答える

    AIから質問があったときだけ、短く答えます。

  • 03仕上げる

    仕上げ用のプロンプトを送り、完成品を受け取ります。

入力してはいけない情報

組織の規定でAIへの入力が認められていない情報は、入力しないでください。個人名や会社名は、必要に応じて「Aさん」「B社」のように置き換えてから使います。

最低動作モデルとは

ソフトウェアの「動作環境」と同じ考え方です。各レシピには、どのAIで動作を確かめたかを表示しています。古いモデルでも使えることを大切にしているため、最新のAIでなくても安心して試せます。「未検証」と表示されているレシピは、まだ確認が済んでいません。

最後は人が確認する

AIの出力は下書きです。各レシピの「最後に確認すること」だけは、共有する前に必ず確認してください。

Help

長すぎて送れないとき

組織向けのAIサービスには、1回に送れる文字数に上限があることがあります。各レシピのページで、プロンプトの文字数を確認できます。

  1. プロンプトと資料を分けて送る
    プロンプトを、資料を貼らずにそのまま送ります。「貼り付けてください」と返ってきたら、次のメッセージで資料だけを送ります。
  2. 資料も何回かに分けて送る
    レシピのページにある定型文を先に送ってから、資料を区切って送り、最後に「以上です」と送ります。
  3. 資料を区切って使う
    それでも難しいときは、資料を内容のまとまりごとに分けて、それぞれでレシピを使ってください。
