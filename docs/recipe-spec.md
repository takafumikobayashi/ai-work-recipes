# Recipe共通仕様

## 目的

Recipeを読む人が、目的・準備・実行・確認・限界を一つの文書で理解できるようにする。新しいRecipeは、原則として [../recipes/template.md](../recipes/template.md) を複製して作成する。

## 必須メタデータ

```yaml
id: 001-meeting-minutes
title: 文字起こしから議事録を作る
status: Draft
version: 0.1.0
audience: [beginner, constrained-environment]
minimum_model: 未確認
tested_models: []
last_tested: YYYY-MM-DD
estimated_time: 目安
input_types: []
output_types: []
confidentiality: 入力可否と注意事項
```

`minimum_model` は、実際に確認してから具体的なモデル名を書く。確認前は `未確認` とし、推測で埋めない。

## 必須セクション

### 1. これは何をするRecipeか

作業の目的を一文で書く。利用後に何が完成すれば成功かも定義する。

### 2. 使う前に

対象者、必要な入力、準備、入力してはいけない情報、所要時間の目安を書く。

### 3. 手順

番号付きで、利用者が迷わない順序にする。各ステップに次の内容を含める。

- 入力するもの
- 使うプロンプト
- 期待する出力
- 次のステップへ進む条件
- 人間が確認する箇所

### 4. なぜこの手順でうまくいくのか

処理を分ける理由、モデルの誤りを見つけやすくする工夫、初心者でも再現しやすくする工夫を書く。

### 5. 限界と注意点

苦手な入力、品質が下がる条件、機密性、誤りの影響、代替策を書く。

### 6. 評価・テスト結果

使用したテスト例、モデル、確認日、評価項目、結果、残った課題を書く。未確認の項目は未確認と明記する。

### 7. 改訂履歴

日付、版、変更内容、変更理由を短く残す。

## 推奨セクション

- 入力例・出力例
- よくある失敗と対処
- 省力化できる箇所と、省略してはいけない確認
- コミュニティからのフィードバック

## Recipeの状態

| 状態 | 意味 |
|---|---|
| `Draft` | 手順案はあるが、評価が不十分 |
| `Tested` | テストセットで確認し、結果を記録済み |
| `Community-tested` | 複数の利用者または実際の現場で検証済み |
| `Stable` | 既知の制約が整理され、定期的な見直し対象になっている |

状態を上げるときは、Recipe本文のテスト結果と改訂履歴を更新する。
