# 設計と検証：まずは1つ、ゲームを作ってみる

技術者・改善に参加したい人向けの文書。プロンプトがなぜこの形になっているのか、苦手なケース、評価方法を説明する。

利用者向けの使い方はWebサイトに表示する。その素材は [page.md](page.md)（カード・使い方・注意）と [prompts/](prompts/)（コピー用プロンプト）にある。

## 1. 設計目標

> **プログラミングもAIも使ったことがない人が、何も書き換えずにプロンプトを貼るだけで、遊べるゲームを1つ作り、一言の頼み方でゲームを変える体験ができること。**

[AIと相談しながら、ブラウザーで遊べるゲームを作る](../browser-game/) の超初心者版。企画を相談する前の「まず1つ動いた」という体験と、「一言で変えられる」というアレンジの入口を目的にする。地域のイベントや教室で、最初の5分に全員が同じものを作る場面も想定している。

## 2. この仕事の分解

利用者がすることは、貼ることだけにした。そのために、[browser-game](../browser-game/) のSTEP 1でAIが提案する内容（目的、流れ、画面、操作、得点、制限時間、終了）を、あらかじめプロンプトの中で決めてある。作り方の条件（HTML1ファイル、外部の読み込みなし、個人の情報なし、外部リンクなし、全文を省略しない）は、browser-game と同じにした。

```text
STEP 1　固定のプロンプトを貼る → HTMLの全文 ＋ 一言の頼み方の例3つ → 保存して遊ぶ
    ↓
STEP 2　（必要なら）一言で変える
```

### 題材の選び方

| 条件 | 「ふうせんわりゲーム」で満たしていること |
|---|---|
| 説明なしで遊べる | 出てきたものを押すだけ |
| 古いモデルでも1回で動きやすい | 要素の生成・移動・クリック・タイマーだけの、よくある構造 |
| 絵文字だけで成り立つ | 🎈は、ほとんどの端末で表示できる |
| アレンジしやすい | 絵文字・時間・点数・背景・特別なふうせんを、一言で変えられる |
| 年齢を問わない | 子どもも大人も遊べ、こわい表現がない |

[browser-game](../browser-game/) の判断基準のとおり、再スタートでタイマーが二重になる不具合が起きやすい。このため、`page.md` の「最後に確認すること」に、もう一度あそぶを続けて押す確認を入れた。

### 一言の頼み方の例を出させる理由

[first-illustration](../../design/first-illustration/) と同じ。利用者が次に何を頼めばよいかで止まらず、「変えたいところだけを、短く頼む」型を体験から覚えられるようにする。browser-game のSTEP 3（機能を1つだけ足す）への橋渡しになる。

## 6. 使っている設計パターン

| パターン | このRecipeでの使い方 |
|---|---|
| P3 禁止事項を具体的に書く | 外部の読み込み、個人の情報、外部リンク、コードの省略 |
| P5 出力フォーマットを固定する | HTMLの全文（1つのコードブロック） ＋ 一言の頼み方の例3つ |

## 7. 限界と注意点

- 一言のアレンジを重ねると、AIが全体を作り直して、前に動いていたところが壊れることがある。壊れたら、browser-game のSTEP 4（直す）のプロンプトを使う
- AIはゲームを動かして確かめられない。動作の確認は、利用者が遊んで行う
- 絵文字の見た目は、端末によって違う

### 確認すること

| 評価項目 | 確認内容 |
|---|---|
| 一度で動くか | 書き換えずに貼って、保存してすぐ遊べるか |
| 遊び方 | スタート、ふうせんの出現と上昇、割れて1点、だんだん増える、30秒で終了、点数の表示、もう一度あそぶ |
| 再スタート | 続けて押しても、時間の進み方や点数がおかしくならないか |
| 端末 | スマートフォンの縦の画面で、指で遊べるか |
| 頼み方の例 | 一言の頼み方の例が3つ出るか。そのまま送ってゲームが変わり、動くか |
