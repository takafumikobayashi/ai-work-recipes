# 設計と検証：地域イベントのチラシ画像を作る

技術者・改善に参加したい人向けの文書。プロンプトがなぜこの形になっているのか、苦手なケース、評価方法を説明する。

利用者向けの使い方はWebサイトに表示する。その素材は [page.md](page.md)（カード・使い方・注意）と [prompts/](prompts/)（コピー用プロンプト）にある。

## 1. 設計目標

> **地域団体などでイベントを担当する人が、画像を作れるAIで、確認済みの原稿から、印刷やSNSに使えるチラシ画像を、誤った文字や作られた情報を載せずに作れること。**

「デザイン」カテゴリの最初のRecipe。[地域イベントのチラシ・SNS文章を作る](../../writing/event-copy-from-memo/) の後段として使うことを想定している。文章の事実確認はそちらで済ませ、このRecipeは「確認済みの文字を変えずに、見栄えのよい1枚にする」ことだけを担う。

### 他のRecipeとの違い

- **最低動作モデルをGPT-4.1にできない**。GPT-4.1は画像を生成できないため、作成者が動作を確認した Gemini 3.8 Flash とした。組織の環境で画像生成が使えない利用者は対象外になる。この点は `page.md` の「使う前に」の先頭に書いた
- **AIが成果物を自分で確認できない**。テキストのRecipeでは、セルフチェック（P8）で一定の誤りを防げる。画像の中の文字は、生成したモデル自身も正しく読み返せないことが多く、セルフチェックが働かない。確認は必ず人間が行う設計にした

## 2. この仕事の分解

「このイベントのチラシを作って」と画像を作るAIに頼むと、AIは次の仕事を同時に求められている。

1. 載せる文章を考える（キャッチコピー、紹介文、日時・会場などの事実）
2. 事実を正しく保つ
3. 絵柄・構図・色を決める
4. 文字を正確に描く

1と2は [event-copy-from-memo](../../writing/event-copy-from-memo/) に任せ、このRecipeでは3と4だけを扱う。4は現在の画像生成モデルで最も不安定な部分であるため、利用者が「文字も画像に入れる（A）」か「文字の欄を空けておく（B）」かを選べるようにした。

```text
確認済みの原稿（イベント名・キャッチコピー・紹介文・基本情報）＋ 絵のイメージ
    ↓
STEP 1　画像を作る（A：文字も入れる／B：紹介文と基本情報の欄を空ける）
    ↓
STEP 2　必要なら、直したいところだけを直す
    ↓
STEP 3　人間が文字を確認する。Bの場合は文字を載せる。問い合わせ先・地図・QRコードを貼る
```

### 元の案からの変更

このRecipeは、利用者が確定した本文・開催情報・ビジュアル要件を入れて画像を1枚作るプロンプトとして提案された。文字を変えないこと、事実を作らないこと、地図・ロゴ・QRコード・電話番号・住所を作らせず枠だけを設けること、レイアウトの指定は、その案を引き継いだ。次の点を変えた。

| 元の案 | 変更 | 理由 |
|---|---|---|
| 本文を必ず画像に入れる | A（文字も入れる）とB（欄を空けて後から載せる）を選べるようにし、Bをおすすめにした | 180〜220字の日本語を、画像生成モデルが一字も違えずに描くのは難しい。印刷して配るチラシでは、文字の誤りが致命的になる |
| 「本文が正確に入っていない場合は完成とみなさない」 | 削除し、STEP 3で人間が一字ずつ確認する | モデルは自分の描いた文字を正しく検証できないため、この指示は守られたように見えるだけになる |
| 「本文以外の文字を追加しない」と「上部にイベント名を大きく配置」 | 画像に入れる文字を「掲載する文字」（イベント名・キャッチコピー・紹介文・基本情報）として列挙し、それ以外を禁止 | 元の案では、イベント名や開催情報が「本文以外の文字」に当たり、指示が矛盾していた |
| 開催情報は開催日・会場・参加費の3項目 | 基本情報をまとめて貼る欄にした | event-copy-from-memo の出力「C. チラシに載せる基本情報」をそのまま貼れるようにするため |
| ビジュアル要件9項目 | 7項目にまとめ、書かない項目は原稿の内容に合わせて決めさせる | すべて埋めなくても使えるようにする。「道具・機械」は「入れたいもの」に含めた |
| ― | 【要確認】が残っている原稿では画像を作らない | 未確定の情報がチラシに載るのを防ぐ |
| ― | 有名な作品・キャラクター・特定の作家の絵柄に似せることを禁止 | 団体の名前で配るチラシで、著作権の問題を避ける |
| ― | STEP 2として、直したいところだけを直すプロンプトを追加 | 画像は一度で決まらないことが多い。直すたびに文字が変わる問題があるため、「それ以外は変えない」と明記し、`page.md` で再確認を促す |

## 3. 判断基準

### 画像に入れてよい文字

| 文字 | 扱い |
|---|---|
| イベント名、キャッチコピー | 入れる（A・Bとも）。短いため、比較的正確に描ける |
| 紹介文、基本情報 | Aは入れる。Bは欄を空ける |
| 電話番号、メールアドレス、住所、URL | 入れない。白い枠だけ |
| 地図、QRコード、ロゴ | 作らない。白い枠だけ |
| 原稿にない見出し・飾り文字（「Welcome!」「お楽しみに」など） | 入れない |

数字と連絡先を画像に描かせないのは、誤りが参加者の行動を直接誤らせるうえ、見た目では気づきにくいためである。

## 4. 中間フォーマット

テキストのRecipeのような中間出力はない。代わりに、入力の形を event-copy-from-memo の出力に合わせている。

| event-copy-from-memo の出力 | このRecipeの欄 |
|---|---|
| A. キャッチコピー（おすすめの1案） | キャッチコピー |
| B. チラシ用の紹介文 | 紹介文 |
| C. チラシに載せる基本情報 | 基本情報 |
| C の「イベント名」 | イベント名 |

## 5. 人間への確認

AIからの質問は設けていない。原稿は確定済みで、絵のイメージは書かない項目をAIに任せられるため。AIが応答だけして画像を作らないのは、原稿に【要確認】が残っている場合と、原稿が貼られていない場合に限る。

人間の確認は、STEP 3と「最後に確認すること」に集約した。とくに文字の照合は、AIに任せられない。

## 6. 使っている設計パターン

共通のパターンは [docs/prompt-patterns.md](../../../docs/prompt-patterns.md) を参照。テキスト向けのパターンのうち、画像に適用できるものだけを使っている。

| パターン | このRecipeでの使い方 |
|---|---|
| P3 禁止事項を具体的に書く | 条件の描き足し（無料、予約不要、先着）、架空のロゴ・団体名、絵柄の模倣、読めない文字 |
| P4 分からないことの書き方を決める | 【要確認】が残る原稿では作らない。連絡先・地図は白い枠にする |
| P5 出力フォーマットを固定する | レイアウト（A4縦、上部にイベント名、下部に文字欄と情報ボックス、下端に白い枠） |
| P6 中間出力を次の入力にする | event-copy-from-memo の出力A・B・Cを、そのまま「掲載する文字」にする（4章） |
| P8 セルフチェック | 使わない。画像の文字はモデル自身が検証できないため、人間の確認に置き換えた |
| P10 文字数の上限に備える | プロンプトと原稿で2,000字程度に収まるため、特別な手順は設けない |

## 7. 限界と注意点

- 画像生成ができないAIでは使えない
- Aでは、文字の誤り（字形の崩れ、似た字への置き換え、脱字・重複）が起きやすい。とくに長い紹介文と、画数の多い漢字
- STEP 2で直すと、直していない部分の文字や絵が変わることがある
- 画像の解像度は、サービスによっては印刷（A4、300dpi）に足りないことがある
- 生成画像の商用利用・著作権の扱いは、使うサービスの規約による
- 実在の場所（特定の寺社、駅など）を正確に描くことはできない。似せようとすると、誤った建物が描かれる

検証するサービスとモデルは、利用者が組織で使える可能性の高いものから選ぶ。

### テストケース

event-copy-from-memo のテストケースのSTEP 3の出力を、原稿として使う。テストセット（`evals/`）は未作成。

| ケース | 内容 | 確かめること |
|---|---|---|
| 1. 標準・A | 秋まつり、紹介文200字前後 | 文字の正確さ（誤字・脱字の数）、原稿にない文字の有無 |
| 2. 標準・B | 1と同じ原稿 | 欄を空けられるか。空いた欄に文字を載せる広さがあるか |
| 3. 【要確認】あり | 参加費が【要確認】の原稿 | 画像を作らずに止まるか |
| 4. イメージ未記入 | 絵のイメージをすべて空欄 | 原稿の内容に合った絵になるか |
| 5. 修正 | 1の画像に、誤字1か所の修正を依頼 | 指定した箇所以外が変わらないか |

### 評価指標

| 評価項目 | 確認内容 |
|---|---|
| 文字の正確さ（A） | 原稿と一字ずつ比べた誤り（誤字・脱字・追加）の数 |
| 作られた情報 | 原稿にない文字・条件・団体名・ロゴ・連絡先がないか |
| 枠の確保 | Bの文字欄、下端の白い枠が、使える広さで空いているか |
| 読みやすさ | 文字とイラストが重なっていないか。A4に印刷して紹介文が読めるか |
| 絵の適切さ | 内容・季節・対象に合っているか。暗い表現や特定の作品に似た絵柄がないか |
| 修正の安定性 | STEP 2で、指定した箇所以外が変わらないか |
