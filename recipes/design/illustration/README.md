# 設計と検証：用途に合わせたイラストを作る

技術者・改善に参加したい人向けの文書。プロンプトがなぜこの形になっているのか、苦手なケース、評価方法を説明する。

利用者向けの使い方はWebサイトに表示する。その素材は [page.md](page.md)（カード・使い方・注意）と [prompts/](prompts/)（コピー用プロンプト）にある。

## 1. 設計目標

> **画像生成に慣れていない人が、用途と描きたいものを短く書くだけで、頼んでいないものや文字が入らず、後から文字を載せられる余白つきのイラストを作れること。**

「デザイン」カテゴリの2本目のRecipe。チラシ、Webサイト、SNS、発表資料の表紙など、文字を後から載せる前提のイラストを対象にする。[地域イベントのチラシ画像を作る](../event-flyer/) が「確認済みの文字を載せた1枚」を作るのに対し、このRecipeは文字を一切入れず、絵だけを作る。

## 2. この仕事の分解

「〇〇のイラストを作って」という短い指示の裏で、AIは次の仕事を同時に求められている。

1. 用途から、向き・縦横比・余白を決める
2. 描くもの（人物・物・場所）を決める
3. 構図（主役・前景・中景・背景）を決める
4. 画風・色・雰囲気を決める
5. 描かないもの（文字、ロゴ、頼んでいないもの）を守る
6. 絵を描く

短い指示では1〜4をAIが自由に補い、利用者の想定と違う絵になる。一方、1〜5をすべて利用者に書かせると、約30項目の記入が必要になる。そこで、1〜5を「イラストの設計書」としてAIに下書きさせ、利用者が確認してから6に進む。

```text
作りたい絵のメモ（＋任意の参考画像）
    ↓
STEP 1　用途の把握 → 設計書（メモの項目はそのまま、ない項目は「（提案）」）（＋必要な場合だけ質問）
    ↓
STEP 2　利用者が質問に答え、（提案）を直す
    ↓
STEP 3　設計書に沿って1枚を作る
    ↓
STEP 4　（必要なら）直したいところだけを直す
```

### 元の案からの変更

このRecipeは、約30項目の記入欄を持つイラスト生成のテンプレートとして提案された。あわせて、テンプレートを中学生の科学部の発表資料の表紙に当てはめた記入例で、検証が行われた（画像の向き・余白・必ず入れるもの・入れないものの指定が、意図どおりに働くことを確認）。設計書の項目、参考画像の扱い、文字を入れないこと、入れないものの考え方は、その案を引き継いだ。次の点を変えた。

| 元の案 | 変更 | 理由 |
|---|---|---|
| 利用者が約30項目を記入する | 利用者は5行程度のメモを書き、AIが設計書に展開する。元のテンプレートは、STEP 1の出力形式（設計書）として使う | 初心者には記入の負担が大きい（[design-principles.md](../../../docs/design-principles.md) の原則3）。記入例が示すとおり、項目が埋まっていれば品質は出るため、埋める作業をAIに任せる |
| ― | AIが補った項目に「（提案）」と付ける | 利用者が、自分で決めたことと、AIが決めたことを見分けられるようにする |
| 実在場所の扱い：再現する／架空にする | 指定がなければ架空にする。実在の場所の再現を求められたら質問する | 画像生成モデルは実在の場所を正確に描けず、似ているが違う絵は、見る人に誤解を与える |
| 必ず入れるもの：4項目の欄 | 7つまで | 記入例では7つを指定して成立した。それ以上は、一つひとつが小さくなり、描かれないものが出やすい |
| 入れないもの：固定の一覧（田んぼ、都市的な建物など） | このイラストで起こりそうな失敗だけを5つ程度、AIに選ばせる | 記入例で、元のテンプレートの田園向けの既定値を打ち消すために「田んぼ、山、農業」を入れないものに書く必要があった。また、画像生成モデルは、否定の形でも書かれた語に引きずられて描くことがある |
| 生成後の確認（AIのセルフチェック） | 削除し、`page.md` の「最後に確認すること」で人間が確認する | 画像生成モデルは、自分の描いた画像を正確に検証できない。確認したように見えるだけになる |
| ― | STEP 4として、直したいところだけを直すプロンプトを追加 | [event-flyer](../event-flyer/) と同じ理由 |
| ― | 参考画像は、自分で撮った写真や、使用の許可がある画像に限る（`page.md`） | 他人の作品の絵柄をまねることを避ける |

設計書を自分で書ける利用者のために、STEP 3のプロンプトだけを使い、設計書を貼る使い方も残した（`page.md` の「長すぎて送れないとき」）。

## 3. 判断基準

### メモの項目と（提案）

| メモの例 | 設計書での扱い |
|---|---|
| 「右側を空けたい」 | 文字を後から置く余白：右側（メモのとおり） |
| 余白の指定なし、用途は「発表資料の表紙（横長）」 | 余白：右側または上部（提案） |
| 「中学生4〜5人」 | 必ず入れるもの：中学生の男女4〜5人、それぞれ違う作業をしている（人数はメモのとおり、作業の内容は提案） |
| 「〇〇駅前の風景」 | 質問する（実在の場所をそのまま描くか、雰囲気だけにするか） |
| 「〇〇（アニメ作品）の絵柄で」 | 設計書に書かない。絵柄の特徴（明るい色、太い輪郭線など）に言い換えるかを質問する |

### 入れないもの

入れないものは「このイラストで実際に起こりそうな失敗」に絞る。すべての用途に共通する文字・ロゴ・透かしは、STEP 3のプロンプトの「文字について」で毎回指示するため、設計書では繰り返さなくてよい。

## 4. 中間フォーマット

STEP 1の「イラストの設計書」。用途、基本設定、必ず入れるもの、表現したいこと、構図、スタイル、入れないもの、参考画像の使い方の8つの見出しで、元のテンプレートの項目をほぼそのまま使っている。STEP 3は、この設計書と利用者の変更だけを根拠にする。

## 5. 人間への確認

| 質問する場面 | 理由 |
|---|---|
| 用途が分からない | 向き・縦横比・余白が決まらない |
| 必ず入れるものが多すぎる、または矛盾する | 描かれないもの、不自然な絵が出る |
| 実在の場所・人物をそのまま描くよう求められた | 誤解を招く絵や、肖像の問題を避ける |

画風・色・構図などの好みは質問しない。（提案）として書かせ、利用者が変えたいときだけ伝える。

## 6. 使っている設計パターン

共通のパターンは [docs/prompt-patterns.md](../../../docs/prompt-patterns.md) を参照。

| パターン | このRecipeでの使い方 |
|---|---|
| P1 処理の順序を固定する | 把握 → 設計書 → 確認 |
| P3 禁止事項を具体的に書く | 画像を先に作ること、メモにないものの追加、実在の人物・作品の絵柄、文字・看板・ロゴ |
| P4 分からないことの書き方を決める | メモにない項目は「（提案）」と印を付ける |
| P5 出力フォーマットを固定する | 設計書の8つの見出し |
| P6 中間出力を次の入力にする | 設計書を、STEP 3の唯一の根拠にする |
| P7 必要なときだけ質問する | 用途、必ず入れるものの量・矛盾、実在の場所・人物に限定。3つまで |
| P8 セルフチェック | 使わない。画像の確認は人間が行う |
| P9 入力の区切りと念押し | メモを `↓↓↓` `↑↑↑` で囲む |

## 7. 限界と注意点

- 画像生成ができないAIでは使えない
- 「文字を入れない」と指示しても、文字のような模様が描かれることがある
- 人物の手や指、道具の細かい形が崩れることがある
- STEP 4で直すと、直していない部分も変わることがある
- 実在の場所は正確に描けない
- 生成画像の商用利用・著作権の扱いは、使うサービスの規約による
- 画像の解像度は、印刷に足りないことがある

### テストケース

テストセット（`evals/`）は未作成。

| ケース | 内容 | 確かめること |
|---|---|---|
| 1. 科学部の表紙 | 元の案の記入例を、5行程度のメモにしたもの | 設計書が記入例と同等になるか。（提案）が付くか |
| 2. 地域イベント | 山と田んぼの秋祭り、チラシ用、上部に余白 | 余白が空くか。文字が入らないか |
| 3. 最小のメモ | 「市のWebサイトのトップ画像。海の町」だけ | 質問するか。提案で埋められるか |
| 4. 実在の場所 | 「〇〇駅前の商店街をそのまま」 | 質問するか |
| 5. 作品の絵柄 | 「〇〇（アニメ）風で」 | 設計書に書かず、質問するか |
| 6. 参考画像あり | ロゴと文字の入った写真を添付 | 画風だけを使い、ロゴと文字を再現しないか |

### 評価指標

| 評価項目 | 確認内容 |
|---|---|
| 設計書の正確さ | メモの項目をそのまま使い、補った項目に（提案）が付いているか |
| 必ず入れるもの | すべて描かれているか |
| 描き足し | 設計書にない人物・建物・看板がないか |
| 文字 | 読める文字、文字のような模様、ロゴがないか |
| 余白 | 指定した場所が、文字を置けるだけ空いているか |
| 参考画像 | 画風だけを使い、人物・建物・ロゴを再現していないか |
| 修正の安定性 | STEP 4で、指定した箇所以外が大きく変わらないか |
