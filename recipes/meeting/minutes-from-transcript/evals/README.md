# 評価：文字起こしから議事録を作る

このRecipeを、最低動作モデル（GPT-4.1）で検証するためのテストセットと記録。評価の考え方は [docs/evaluation.md](../../../../docs/evaluation.md)、評価指標は [../README.md](../README.md) の8章を参照。

## テストケース

文字起こしはすべて架空のダミーデータ。人名・団体名は実在のものと関係ない。

| ケース | 内容 | 主に確かめること |
|---|---|---|
| [01-standard](cases/01-standard/) | 地域防災訓練の準備会。決定・担当・期限が明確 | 基本動作。不要な質問をしないか |
| [02-ambiguous](cases/02-ambiguous/) | 業務改善ミーティング。曖昧な合意、話者名なし、「例の件」 | 曖昧な合意を断定しないか。必要な質問をするか |
| [03-conflict](cases/03-conflict/) | 図書館の開館時間延長。賛成・反対・保留が混在 | 意見と結論、決定と持ち越しを分けられるか |
| [04-noisy](cases/04-noisy/) | 公民館の改修。フィラー、言い直し、誤変換、話者不明 | 言い直し後の数字を採用し、固有名詞を勝手に直さないか |
| [05-changed](cases/05-changed/) | 商店街の年末イベント。途中でA案からB案へ、期限も変更 | 最終的な結論と期限を採用できるか |
| [06-long](cases/06-long/) | 自治会の定例役員会。約1万500字、10の議題、日程の変更、個人の健康の話題 | 長い入力での抜け、文字数の上限への対応、安全性 |

各ケースのフォルダには、貼り付ける `transcript.txt` と、正解とよくある誤りを書いた `expected.md` がある。**実施する前に `expected.md` を見ないこと**（作業時間や印象が変わるため。採点のときに開く）。

## 実施条件

| 条件 | 手順 |
|---|---|
| A 通常 | STEP 1のプロンプトの文字起こし欄に `transcript.txt` を貼って送る → 質問があれば答える → STEP 3を送る |
| B 分けて送る | STEP 1のプロンプトをそのまま送る → 「文字起こしを貼り付けてください」と返るか確認 → `transcript.txt` を送る → 以降はAと同じ |
| B2 分割して送る | STEP 1のプロンプトをそのまま送る → [分割送信の定型文](../page.md) を送る → `parts/part1.txt`〜`part3.txt` を順に送る → 「以上です」と送る → 以降はAと同じ（06-longのみ） |
| C 一発指示 | 「以下の文字起こしから議事録を作成してください。」の後に `transcript.txt` を貼って送る（比較の基準） |

### 最初に行う組み合わせ（13回）

| ケース | A 通常 | B 分けて送る | B2 分割して送る | C 一発指示 |
|---|:---:|:---:|:---:|:---:|
| 01-standard | ✓ | ✓ | | ✓ |
| 02-ambiguous | ✓ | | | |
| 03-conflict | ✓ | | | |
| 04-noisy | ✓ | ✓ | | |
| 05-changed | ✓ | | | ✓ |
| 06-long | ✓ | ✓ | ✓ | ✓ |

06-longのAは、サービスの文字数の上限で送れない可能性がある。送れなかった場合は、その事実（エラーの表示内容）を記録シートの「送信できたか」に書き、Bに進む。

余裕があれば、01と05のAをもう一度行い、結果のぶれ（再現性）を見る。

## 実施のルール

- **1回ごとに新しい会話**を始める。前の会話の内容が影響しないようにするため
- 使ったサービス名、モデル名、日付を記録する（同じGPT-4.1でも、サービスによって設定や文字数の上限が違う）
- STEP 2で質問に答えるときは、`expected.md` の内容ではなく、**文字起こしから分かる範囲で**答える。分からないことは「不明です。そのまま進めてください」と答える
- 06-longは採点の項目が多い。網羅性は `expected.md` の「重要な12件」を中心に見る
- 所要時間は、STEP 1のプロンプトをコピーしてから、完成版の議事録を受け取るまでを計る（AIの応答待ちを含む）
- AIの出力は、加工せずにそのまま記録する

## 記録の方法

1. [results/TEMPLATE.md](results/TEMPLATE.md) を複製し、`results/YYYY-MM-DD_<モデル>_<ケース>_<条件>.md` という名前で保存する（例：`2026-10-20_gpt-4.1_01-standard_A.md`）
2. AIの出力（STEP 1、STEP 2のやり取り、STEP 3）を貼る
3. `expected.md` と比べて採点する
4. 全体の結果を、[../README.md](../README.md) の「動作確認モデルと評価」に要約する

## まだ足りないケース

- **さらに長い会議**：06-longは約1万500字で、実際の1時間の会議（1万5千〜2万字程度）よりは短い。ただし雑談や言い直しが少なく情報の密度が高いため、抜けを確かめる条件としては厳しめになっている。06-longで抜けが目立たなければ、より長いケースは後回しにしてよい
- **根拠付き版との比較**：根拠の引用を付けたプロンプトの版は、まだ作っていない
