# 設計と検証：アンケートや問い合わせを分類して一覧にする

技術者・改善に参加したい人向けの文書。プロンプトがなぜこの形になっているのか、苦手なケース、評価方法を説明する。

利用者向けの使い方はWebサイトに表示する。その素材は [page.md](page.md)（カード・使い方・注意）と [prompts/](prompts/)（コピー用プロンプト）にある。

## 1. 設計目標

> **忙しい実務者が、GPT-4.1でも、アンケートの自由記述や問い合わせの一覧を、件数を落とさず、原文を変えずに、決めた基準で分類し、Excelで使える形にできること。**

「情報整理」カテゴリの最初のRecipe。住民アンケート、研修や行事のアンケート、窓口への問い合わせ、パブリックコメントの意見などを対象にする。

- 傾向を文章でまとめる（要約する）ことではなく、**1件ずつに分類を付けること**を目的にする。要約は分類のあとで人間が行うか、別のRecipeで扱う
- 分類の結果は、Excelの元データの横に貼って、集計や絞り込みに使う

## 2. この仕事の分解

「このアンケートを分類して」という短い指示の裏で、AIは次の仕事を同時に求められている。

1. 件数を把握する
2. 内容を把握し、分類の基準を作る
3. 基準を、重なりのない定義にする
4. 1件ずつ、基準に当てはめて判断する
5. 判断できないものを、無理に分類せずに分ける
6. 分類ごとの件数を数える
7. 結果を、元データと対応づけられる形で出す

一度に求めると、1・4・6が崩れやすい。件数が多いと、AIは途中の回答を飛ばしたり、似た回答をまとめたりする。また、分類の基準を作りながら分類すると、途中で基準が変わり、前半と後半で同じ回答の扱いが変わる。そこで、STEP 1で件数の把握と基準づくりを行い、利用者が基準を確かめてから、STEP 3で分類する。

```text
データ
    ↓
STEP 1　件数の把握 → 分類の基準（定義と例）→ 注意が必要な回答（＋基準の確認）
    ↓
STEP 2　利用者が基準を確かめる、変える
    ↓
STEP 3　決めた基準だけで1件ずつ分類 → 件数の集計（＋セルフチェック）
```

議事録やお知らせ文のRecipeと違い、STEP 2の質問（基準の確認）は、利用者が基準を指定しない限り、ほぼ毎回行う。分類の基準は、利用者の目的（何のために分類するか）で決まるため、AIだけでは決められないからである。

## 3. 判断基準

分類そのものの基準は、データと目的によって変わるため、Recipeでは固定しない。代わりに、分類の基準の「作り方」と、基準に当てはまらないものの扱いを定義する。

| 区分 | 意味 |
|---|---|
| 分類（5〜8個） | 定義（何を入れるか）と、データの中の例（番号）を持つ。互いに重ならない |
| その他 | 判断はできるが、どの分類の定義にも当たらない |
| 保留 | 定義に当てはまるか判断できない（内容があいまい、指示語だけ、など） |
| 意見なし | 「特になし」「なし」など、意見が書かれていない |

「その他」と「保留」を分けるのは、人間が後で読むべき回答を絞るため。「保留」は人間が読んで分類し直す対象であり、「その他」は基準を見直すきっかけ（件数が多ければ分類を増やす）になる。

複数の話題を含む回答は、主な話題の分類を1つ付け、備考に「○○にも該当」と書く。1件に複数の分類を付けると、件数の合計が全体と合わなくなり、Excelでの集計も複雑になるため。

## 4. 中間フォーマットと出力の形

STEP 1では次の「箱」に整理させる。

- データの把握（件数、最初と最後の回答の冒頭20字、主な内容）
- 分類の基準の表（分類・定義・例の番号）
- 注意が必要な回答（複数の話題、個人を特定できる情報）

最初と最後の回答を示させるのは、利用者がExcelの行数・先頭・末尾と照らし合わせて、データが正しく渡ったか（貼り付けの欠け、行の分かれ方の違い）を確かめるためである。

STEP 3の一覧は、**番号・冒頭（原文の最初の10字）・分類・備考**とし、原文全体は書き写させない。理由は3つ。

1. 原文を書き写させると、AIが言い換えや要約をして、意味が変わることがある
2. 件数が多いと出力が長くなり、出力の途中で切れやすくなる
3. 利用者は元データをExcelに持っているので、分類の列だけがあればよい

冒頭の10字は、AIが番号と回答を取り違えていないか、利用者が貼り付けたときに行がずれていないかを確かめる手がかりとして残している。

## 5. 人間への確認

| 確認する場面 | 理由 |
|---|---|
| 分類の基準（利用者が指定しない場合） | 何のために分類するかで、適切な基準が変わる |
| 注意が必要な回答（STEP 1で提示のみ） | 個人を特定できる情報の扱いは、組織のルールで決める |

1件ずつの判断について質問させることはしない。件数が多いと質問が増えすぎるため、判断できないものは「保留」として人間に渡す。

## 6. 使っている設計パターン

共通のパターンは [docs/prompt-patterns.md](../../../docs/prompt-patterns.md) を参照。

| パターン | このRecipeでの使い方 |
|---|---|
| P1 処理の順序を固定する | 把握 → 分類の基準 → 注意が必要な回答 → 整理 |
| P2 分類は定義で渡す | 分類の基準を、定義と例（番号）の表にさせる。「その他」「保留」「意見なし」を定義する（3章） |
| P3 禁止事項を具体的に書く | 件数の数え間違い、回答の飛ばし・まとめ、言い換え、STEP 1での分類の開始 |
| P4 分からないことの書き方を決める | 判断できない回答は「保留」と理由 |
| P5 出力フォーマットを固定する | 番号・冒頭・分類・備考の一覧と、件数の表 |
| P6 中間出力を次の入力にする | STEP 1の分類の基準を、STEP 3の唯一の分類の基準にする（新しい分類を作らせない） |
| P7 必要なときだけ質問する | 基準の確認だけ。利用者が基準を書いた場合は質問しない |
| P8 確認対象を指定してセルフチェック | 行数と件数の一致、番号の抜け・重複、合計の一致、基準外の分類名、無理な分類 |
| P9 入力の区切りと念押し | 分類の基準とデータを、それぞれ `↓↓↓` `↑↑↑` で囲む。データの後で「1行を1件」「言い換えない」を再確認させる |
| P10 文字数の上限に備える | データの欄が空のときは待つ指示。`page.md` に、1回100件までの目安と、続きを分類する定型文を載せる |

### 1回100件までとしている理由

件数が多いほど、回答の飛ばしや番号のずれが起きやすくなる。また、一覧の出力が長くなり、出力が途中で切れる可能性が高まる。100件は、自由記述が1件50字程度なら入力で約5,000字、出力で約3,000字程度になり、多くのサービスで扱える量として仮に置いた目安である。テストで、件数と誤りの関係を確かめて見直す。

## 7. 限界と注意点

- 件数の一致や行のずれは、AIのセルフチェックだけでは保証できない。利用者が件数と冒頭の列で確かめる必要がある
- 1つのセルの中に改行がある回答は、Excelからコピーすると複数行に分かれたり、引用符で囲まれたりして、件数がずれることがある
- 分類は、定義に基づくAIの判断であり、件数を政策判断などに使う場合は、人間による確認が必要である
- 皮肉や反語（「大変すばらしい対応でした（笑）」など）は、誤って分類しやすい
- 傾向の要約や、意見への回答文の作成は、このRecipeの範囲外である

### テストケース

架空のアンケート・問い合わせを使う。1〜6は [evals/](evals/) に作成済み。

| ケース | 内容 | 確かめること |
|---|---|---|
| 1. 標準 | 公民館の利用者アンケート（20件） | 基本動作。分類の基準の質、件数の一致 |
| 2. 基準の指定あり | 窓口への問い合わせ（15件）。分類の基準を利用者が指定 | 指定した基準だけで分類できるか（正解表あり） |
| 3. あいまい・複数の話題 | 研修のアンケート（15件） | 保留と、複数の話題の備考を正しく付けられるか |
| 4. 個人情報を含む | 図書館への意見（12件）。職員や利用者の名前、電話番号を含む | 個人を特定できる情報を示せるか |
| 5. 件数が多い | 住民アンケート（60件） | 件数・番号・冒頭がずれないか |
| 6. 短い回答・空の行 | 行事のアンケート（20行）。「特になし」、空の行、1語の回答 | 空の行を数えず、「意見なし」を正しく扱えるか |

### 評価指標

[docs/evaluation.md](../../../docs/evaluation.md) の基本評価項目に加えて、次を記録する。

| 評価項目 | 確認内容 |
|---|---|
| 件数の正確さ | STEP 1の件数、一覧の行数、集計の合計が、正しい件数と一致しているか |
| 対応の正確さ | 番号と冒頭が、元データの同じ行と一致しているか（ずれがないか） |
| 分類の基準の質 | 定義が重ならず、データの内容を覆っているか。目的に合っているか |
| 分類の正確さ | 定義どおりに分類できたか（ケース2は正解表と比べる） |
| 保留の適切さ | 判断できない回答を保留にし、判断できる回答を保留にしていないか |
| 原文の保持 | 冒頭を書き換えていないか。回答を言い換えていないか |
