# 評価：アンケートや問い合わせを分類して一覧にする

このRecipeを、最低動作モデル（GPT-4.1）で検証するためのテストセットと記録。評価の考え方は [docs/evaluation.md](../../../../docs/evaluation.md)、評価指標は [../README.md](../README.md) の8章を参照。

## テストケース

データはすべてテスト用に作った**架空の回答**。人名と電話番号も架空のもので、電話番号は実在しない `000-` で始まる番号を使っている。

| ケース | 内容 | 主に確かめること |
|---|---|---|
| [01-standard](cases/01-standard/) | 公民館の利用者アンケート（20件） | 基本動作。分類の基準の質、件数の一致 |
| [02-given-criteria](cases/02-given-criteria/) | 窓口への問い合わせ（15件）。分類の基準を指定する | 指定した基準だけで分類できるか（正解表あり） |
| [03-ambiguous](cases/03-ambiguous/) | 研修のアンケート（15件） | 保留と、複数の話題の備考 |
| [04-personal-info](cases/04-personal-info/) | 図書館への意見（12件）。名前と電話番号を含む | 個人を特定できる情報を示せるか |
| [05-long](cases/05-long/) | 住民アンケート（60件） | 件数・番号・冒頭がずれないか |
| [06-short-blank](cases/06-short-blank/) | 行事のアンケート（20行。うち4行は空の行） | 空の行を数えず、「意見なし」を正しく扱えるか |

各ケースのフォルダには、貼り付ける `data.txt` と、正解とよくある誤りを書いた `expected.md` がある。**実施する前に `expected.md` を見ないこと**。ただし02は、`expected.md` の冒頭にある「分類の基準」を、プロンプトの「分類の基準」の欄に貼ってから実施する。

`data.txt` と `expected.md` は、スクリプトで同じデータから作っている。件数や冒頭の文字を手で書き写した誤りはない。

## STEP 2での答え方

| ケース | 答え方 |
|---|---|
| 02-given-criteria | 基準の確認を聞かれた場合は「A」と答える |
| その他 | 分類の基準の確認には「A」（このまま進める）と答える |

基準を変えずに進めるのは、ケースごとの結果を比べやすくするため。分類の基準を変える操作（B）は、別に試す。

## 実施条件

| 条件 | 手順 |
|---|---|
| A 通常 | STEP 1のプロンプトのデータ欄に `data.txt` を貼って送る → 基準の確認に答える → STEP 3を送る |
| B 分けて送る | STEP 1のプロンプトをそのまま送る → 「データを貼り付けてください」と返るか確認 → `data.txt` を送る → 以降はAと同じ |
| C 一発指示 | 「以下のアンケートの回答を分類して、件数を数えてください。」の後に `data.txt` を貼って送る（比較の基準） |

### 最初に行う組み合わせ（9回）

| ケース | A 通常 | B 分けて送る | C 一発指示 |
|---|:---:|:---:|:---:|
| 01-standard | ✓ | ✓ | |
| 02-given-criteria | ✓ | | |
| 03-ambiguous | ✓ | | |
| 04-personal-info | ✓ | | |
| 05-long | ✓ | | ✓ |
| 06-short-blank | ✓ | | ✓ |

Cの結果は、「件数が合っているか」（05・06）を中心に比べる。このRecipeで手順を分けた効果が最も出やすいのは、件数の正確さである。

## 実施のルール

- **1回ごとに新しい会話**を始める
- 使ったサービス名、モデル名、日付を記録する
- 所要時間は、STEP 1のプロンプトをコピーしてから、一覧を受け取るまでを計る
- AIの出力は、加工せずにそのまま記録する
- 可能なら、一覧の表をExcelに貼り付けて、行がずれずに貼れるかも記録する（サービスによって、表のコピーのしかたが違うため）

## 記録の方法

1. [results/TEMPLATE.md](results/TEMPLATE.md) を複製し、`results/YYYY-MM-DD_<モデル>_<ケース>_<条件>.md` という名前で保存する（例：`2026-10-20_gpt-4.1_05-long_A.md`）
2. AIの出力を貼り、`expected.md` と比べて採点する
3. 全体の結果を、[../README.md](../README.md) の「動作確認モデルと評価」に要約する

## まだ足りないケース

- **100件を超えるデータ**：`page.md` の「100件ずつに分けて分類する」手順で、番号の続きと基準の一貫性が保てるか
- **1つのセルに改行を含むデータ**：Excelからコピーしたときに、件数がずれるか
- **皮肉や反語を含む回答**：「大変すばらしい対応でした（笑）」のような回答を、誤って分類しないか
