# 設計と検証：ガイドラインから、やるべきことを整理する

技術者・改善に参加したい人向けの文書。プロンプトがなぜこの形になっているのか、苦手なケース、評価方法を説明する。

利用者向けの使い方はWebサイトに表示する。その素材は [page.md](page.md)（カード・使い方・注意）と [prompts/](prompts/)（コピー用プロンプト）にある。

## 1. 設計目標

> **忙しい実務者が、GPT-4.1でも、国や自治体のガイドライン・通知から、自分の組織が何をいつまでにしなければならないかを、原文の箇所つきで短時間に把握できること。**

「読み解く」カテゴリの最初のRecipe。長い文書の要約を目的別に分けたうちの、ガイドライン・通知・手引き向けである。

- 一般的な「要約」とは目的が違う。読みやすい短い文章ではなく、**行動の一覧（何を・誰が・いつまでに）と、その根拠の箇所**を出す
- 原文を読まずに済ませるためではなく、**原文のどこを読めばよいかを絞り込む**ためのもの

## 2. この仕事の分解

「このガイドラインを要約してください」という短い指示の裏で、AIは次の仕事を同時に求められている。

1. 文書の名称・発行元・日付・施行日を把握する
2. 誰に向けた文書かを把握する（対象者が複数ある場合が多い）
3. 求められている行動を抜き出す
4. 文末の表現から、義務・努力義務・推奨・禁止を判定する
5. 例外や条件を、行動とセットで保持する
6. 期限を抜き出す
7. 読み手の立場に関係するものを選ぶ
8. 根拠の箇所（章・節）を保持する
9. 読みやすく編集する

一度に求めると、特に4と5が崩れやすい。要約は文章を短くするほど「〜が望ましい」と「〜しなければならない」の差や、「ただし〜の場合を除く」が消えていくためである。そこで議事録Recipeと同じく、STEP 1で抽出・判定・整理を行い、STEP 3で編集する。

```text
文書
    ↓
STEP 1　把握 → 抽出と判定 → 整理（＋必要な場合だけ質問）
    ↓
STEP 2　読み手が対象者を選ぶ（対象者が複数ある場合など）
    ↓
STEP 3　読み手に関係するものに絞って編集（＋セルフチェック）
```

## 3. 判断基準

この仕事の品質は、文末の表現による区別でほぼ決まる。日本の行政文書の書き方の慣習に沿って定義している。

| 分類 | 文末の表現の例 | 意味 |
|---|---|---|
| 義務 | 「〜しなければならない」「〜すること」「〜ものとする」 | 必ず行うことが求められている |
| 努力義務 | 「〜するよう努める」「〜努めなければならない」 | 努めることが求められている（結果までは求めていない） |
| 推奨 | 「〜が望ましい」「〜することが考えられる」「〜を推奨する」 | 行うことが勧められている |
| 禁止 | 「〜してはならない」「〜しないこと」 | 行ってはいけない |
| 参考 | 例示、事例、背景の説明 | 行動を求めていない |

紛らわしい例：

| 原文の例 | 正しい分類 | よくある誤り |
|---|---|---|
| 「〜するよう努めなければならない」 | 努力義務 | 「しなければならない」に引きずられて義務にする |
| 「例えば、〜等の対策が考えられる」 | 参考（または推奨） | 例示された対策を必須にする |
| 「〜すること。ただし、〜の場合はこの限りでない」 | 義務（例外あり） | 例外を落とす |

「〜ものとする」は、文脈によって義務とも方針の表明とも読めるため、法令用語として厳密には議論がある。このRecipeでは利用者に分かりやすいよう義務として扱い、迷う場合は「分類不明」として原文の表現を残させる。

## 4. 中間フォーマット

STEP 1では次の「箱」に整理させる。

- 文書情報（名称・発行元・発行日・改訂日・施行日・適用日・対象者）
- 文書の目的（3行以内）
- 求められている行動の表（分類・対象者・内容・期限・根拠箇所）
- 改訂による変更点（分かる場合のみ）
- 確認したいこと

表に「対象者」の列を持たせているのは、STEP 3で読み手の立場に応じて絞り込むためである。「根拠箇所」の列は、利用者が原文で確認するための手がかりとして、STEP 3まで残す。

## 5. 人間への確認

このRecipeでは、STEP 2が主に「選ぶ」操作になる。

| 質問する場面 | 理由 |
|---|---|
| 対象者が複数あり、どれに当たるかで行動が変わる | 読み手の立場は文書から分からない。選択肢は文書に出てくる対象者から作らせる |
| 文書の一部しか貼られていないと思われる | PDFのコピーで途中が抜けることが多い。抜けたまま整理すると「義務がない」と誤って伝わる |
| 版や日付が分からない | 改訂の多い文書では、古い版で整理すると誤った行動につながる |

文書の内容の解釈について質問させることはしない。解釈は利用者でなく、発行元や担当部署が判断することだからである。

## 6. 使っている設計パターン

共通のパターンは [docs/prompt-patterns.md](../../../docs/prompt-patterns.md) を参照。

| パターン | このRecipeでの使い方 |
|---|---|
| P1 処理の順序を固定する | 把握 → 抽出と判定 → 整理 → 確認 |
| P2 分類は定義で渡す | 文末の表現の例つきで、義務・努力義務・推奨・禁止・参考を定義（3章） |
| P3 禁止事項を具体的に書く | 努力義務・推奨の義務扱い、例示の必須扱い、法的な解釈など |
| P4 分からないことの書き方を決める | 「不明」「分類不明」（原文の表現を残す）、STEP 3では「要確認」 |
| P5 出力フォーマットを固定する | 行動の表（分類・対象者・内容・期限・根拠箇所） |
| P6 中間出力を次の入力にする | STEP 1の表をSTEP 3で対象者に応じて絞り込む |
| P7 必要なときだけ質問する | 対象者の選択、文書の欠け、版の確認に限定（5章） |
| P8 確認対象を指定してセルフチェック | 推測の追加、義務への格上げ、例外の欠落、根拠箇所の欠落、立場の取り違え |
| P9 入力の区切りと念押し | 文書を `↓↓↓` `↑↑↑` で囲み、文書の後で分類の原則を再確認させる |
| P10 文字数の上限に備える | 文書の欄が空のときは待つ指示。`page.md` に、概要版・新旧対照表の利用、分割送信、章ごとの利用を載せる |

### 根拠箇所を必須にしている理由

議事録Recipeでは、出力が長くなるため根拠の引用を付けさせていない。このRecipeでは、章・節の番号を付けさせている。行政文書には番号付きの見出しがあるため短く書け、利用者が原文で確認するときの効果が大きいためである。

## 7. 限界と注意点

- このRecipeは文書の記載を整理するもので、法的な判断・解釈はしない。解釈に迷う場合は、発行元や担当部署に確認する
- 画像だけのPDF（スキャンした文書）は、文字をコピーできないため使えない
- PDFからのコピーでは、表、脚注、段組みが崩れやすい。表の中に重要な義務や期限が書かれている場合は、抜けや取り違えが起きやすい
- 別の文書（法令、別の通知、別紙）を参照している部分は、参照先の内容までは分からない
- 長い文書では、1回の入力に収まらないことが多い。分割して送ると、後半の抜けが増える可能性がある
- 最新の版であるかは、AIには判断できない。発行元のWebサイトで確認する

### テストケース（作成予定）

実在の行政文書をそのまま使うと、改訂で内容が変わり、正解が古くなる。テスト用には、架空の発行元による架空のガイドラインを作る（実在の省庁や自治体の名前は使わない）。

| ケース | 内容 | 確かめること |
|---|---|---|
| 1. 短い通知 | 義務と期限が明確な数ページの通知 | 基本動作 |
| 2. 表現の混在 | 「しなければならない」「努めなければならない」「望ましい」「考えられる」が混在 | 文末の表現による分類 |
| 3. 対象者が複数 | 都道府県・市町村・事業者でそれぞれ求めることが違う | 対象者の質問と、STEP 3での絞り込み |
| 4. 例外・条件付き | 「ただし〜の場合を除く」「〜の場合に限り」が多い | 例外を落とさないか |
| 5. 改訂版 | 新旧対照表つきの改訂通知 | 変更点の抽出 |
| 6. 途中で切れた文書 | 本文の途中までしか貼られていない | 文書の欠けを質問できるか |
| 7. 長い文書 | 数十ページ相当 | 抜けの増え方、文字数の上限への対応 |

### 評価指標

[docs/evaluation.md](../../../docs/evaluation.md) の基本評価項目に加えて、次を記録する。

| 評価項目 | 確認内容 |
|---|---|
| 分類精度 | 義務・努力義務・推奨・禁止を、文末の表現どおりに分類できたか |
| 例外の保持 | 例外や条件を、行動とセットで残せたか |
| 期限の正確さ | 期限・施行日を正しく抜き出し、推測で作っていないか |
| 根拠箇所の正確さ | 章・節の番号が原文と一致しているか |
| 絞り込みの正確さ | 読み手の立場に関係するものだけに、正しく絞れたか |
| 質問品質 | 対象者の選択など、必要な質問だけをしているか |
| 作業時間 | 原文を読み通す場合と比べて、時間を短縮できたか |
