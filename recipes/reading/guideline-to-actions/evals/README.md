# 評価：ガイドラインから、やるべきことを整理する

このRecipeを、最低動作モデル（GPT-4.1）で検証するためのテストセットと記録。評価の考え方は [docs/evaluation.md](../../../../docs/evaluation.md)、評価指標は [../README.md](../README.md) の8章を参照。

## テストケース

文書はすべてテスト用に作った**架空の文書**。「みどり県」「みどり市」「地域安全庁」は実在しない。メールアドレスは例示用のドメイン（`example`）を使っている。

| ケース | 内容 | 主に確かめること |
|---|---|---|
| [01-short-notice](cases/01-short-notice/) | 県から市町村への通知。備蓄品の点検と報告 | 基本動作。報告期限と使用期限を取り違えないか |
| [02-mixed-expressions](cases/02-mixed-expressions/) | 地域イベントの安全管理ガイドライン。文末の表現が混在 | 「努めなければならない」「努めるものとする」を義務にしないか |
| [03-multiple-targets](cases/03-multiple-targets/) | 空き家の見守りの手引き。県・市町村・自治会等・事業者 | 対象者を質問し、選んだ立場に絞れるか |
| [04-exceptions](cases/04-exceptions/) | 公民館の利用指針。「ただし」「を除く」が多い | 例外・条件を落とさないか |
| [05-revision](cases/05-revision/) | 名簿の取扱要領の改正通知。新旧対照表つき | 改正前と改正後を取り違えないか |
| [06-truncated](cases/06-truncated/) | 会計事務の手引き。3章の途中で切れている | 文書の欠けを指摘できるか |

各ケースのフォルダには、貼り付ける `document.txt` と、正解とよくある誤りを書いた `expected.md` がある。**実施する前に `expected.md` を見ないこと**。

## STEP 2での答え方

実施する人によって結果が変わらないよう、STEP 2の答え方を決めておく。

| ケース | 答え方 |
|---|---|
| 03-multiple-targets | 立場を聞かれたら「自治会等」を選ぶ |
| 06-truncated | 続きを聞かれたら「続きはありません。このまま進めてください」と答える |
| その他 | 文書から分かる範囲で答える。分からないことは「不明です。そのまま進めてください」と答える |

## 実施条件

| 条件 | 手順 |
|---|---|
| A 通常 | STEP 1のプロンプトの文書欄に `document.txt` を貼って送る → 質問があれば答える → STEP 3を送る |
| B 分けて送る | STEP 1のプロンプトをそのまま送る → 「文書を貼り付けてください」と返るか確認 → `document.txt` を送る → 以降はAと同じ |
| C 一発指示 | 「以下のガイドラインを要約してください。」の後に `document.txt` を貼って送る（比較の基準） |

### 最初に行う組み合わせ（9回）

| ケース | A 通常 | B 分けて送る | C 一発指示 |
|---|:---:|:---:|:---:|
| 01-short-notice | ✓ | | |
| 02-mixed-expressions | ✓ | ✓ | ✓ |
| 03-multiple-targets | ✓ | | ✓ |
| 04-exceptions | ✓ | | |
| 05-revision | ✓ | | |
| 06-truncated | ✓ | | |

Cの結果は、「義務と推奨の区別が残っているか」「例外が残っているか」を中心に比べる。

## 実施のルール

- **1回ごとに新しい会話**を始める
- 使ったサービス名、モデル名、日付を記録する
- 所要時間は、STEP 1のプロンプトをコピーしてから、まとめを受け取るまでを計る
- AIの出力は、加工せずにそのまま記録する

## 記録の方法

1. [results/TEMPLATE.md](results/TEMPLATE.md) を複製し、`results/YYYY-MM-DD_<モデル>_<ケース>_<条件>.md` という名前で保存する
2. AIの出力を貼り、`expected.md` と比べて採点する
3. 全体の結果を、[../README.md](../README.md) の「動作確認モデルと評価」に要約する

## まだ足りないケース

- **長い文書**：数十ページ相当の架空のガイドライン。抜けの増え方と、文字数の上限への対応（分けて送る、分割して送る、章ごとに使う）を確かめる
- **PDFからのコピーで崩れた文書**：表や段組みが崩れた文字の並び。今のケースは、きれいなテキストを前提にしている
