# 評価：利用規約・約款から、確認すべき条項を整理する

このRecipeを、最低動作モデル（GPT-4.1）で検証するためのテストセットと記録。評価の考え方は [docs/evaluation.md](../../../../docs/evaluation.md)、評価指標は [../README.md](../README.md) の8章を参照。

## テストケース

規約・約款はすべてテスト用に作った**架空の文書**。「みどり」で始まる事業者・サービス・裁判所は実在しない。実在の事業者の規約を使わないのは、改定で正解が古くなることと、特定の事業者の規約を評価しているように見えることを避けるためである。

| ケース | 内容 | 主に確かめること |
|---|---|---|
| [01-standard](cases/01-standard/) | クラウドストレージの利用規約 | 基本動作。振り分けと条項番号、ただし書き |
| [02-renewal](cases/02-renewal/) | 学習サービスの会員規約。無料体験、自動更新、返金なし、解約手数料 | 日数・金額を変えずに示せるか。返金なしの例外を残せるか |
| [03-data-use](cases/03-data-use/) | AI翻訳サービスの規約。無料版とビジネス版 | 学習への利用と、利用しない設定の範囲（選択の後に入力されたものだけ）を示せるか |
| [04-disclaimer](cases/04-disclaimer/) | マーケットの出品者規約。一方的な変更、免責、賠償の上限 | 2か所の「故意または重大な過失」の例外を落とさないか |
| [05-insurance](cases/05-insurance/) | 傷害保険の約款の抜粋 | 支払わない場合のただし書き、告知・通知の義務、30日・3年の期限 |
| [06-missing-annex](cases/06-missing-annex/) | 法人向けサービスの約款。料金は別表で、別表がなく、途中で切れている | 欠けている文書を質問し、額を推測しないか |

各ケースのフォルダには、貼り付ける `document.txt` と、正解とよくある誤りを書いた `expected.md` がある。**実施する前に `expected.md` を見ないこと**。

`expected.md` の「原文に含まれるべき語句」は、すべて `document.txt` の中に一字一句そのまま存在することを、スクリプトで確かめてある。

## STEP 2での答え方

| ケース | 答え方 |
|---|---|
| 02-renewal | プランを聞かれたら「C：わからない」と答える |
| 03-data-use | 無料版かビジネス版かを聞かれたら「無料版です」と答える。抜粋かを聞かれたら「抜粋です。そのまま進めてください」と答える |
| 05-insurance | 抜粋や保険証券・特約について聞かれたら「抜粋です。そのまま進めてください」と答える |
| 06-missing-annex | すべての質問に「わかりません。そのまま進めてください」と答える |
| その他 | 文書から分かる範囲で答える。分からないことは「わかりません。そのまま進めてください」と答える |

## 実施条件

| 条件 | 手順 |
|---|---|
| A 通常 | STEP 1のプロンプトの文書欄に `document.txt` を貼って送る → 質問があれば答える → STEP 3を送る |
| B 分けて送る | STEP 1のプロンプトをそのまま送る → 「文書を貼り付けてください」と返るか確認 → `document.txt` を送る → 以降はAと同じ |
| C 一発指示 | 「以下の利用規約を要約し、注意すべき点を教えてください。」の後に `document.txt` を貼って送る（比較の基準） |

### 最初に行う組み合わせ（9回）

| ケース | A 通常 | B 分けて送る | C 一発指示 |
|---|:---:|:---:|:---:|
| 01-standard | ✓ | ✓ | |
| 02-renewal | ✓ | | |
| 03-data-use | ✓ | | ✓ |
| 04-disclaimer | ✓ | | ✓ |
| 05-insurance | ✓ | | |
| 06-missing-annex | ✓ | | |

Cの結果は、「ただし書きが残っているか」（03・04）と「有利・不利や有効・無効の判断が混ざっていないか」を中心に比べる。一発指示の「注意すべき点」は、AIが判断を書き始めやすい頼み方であり、このRecipeが避けている失敗が最も出やすい。

## 実施のルール

- **1回ごとに新しい会話**を始める
- 使ったサービス名、モデル名、日付を記録する
- 所要時間は、STEP 1のプロンプトをコピーしてから、まとめを受け取るまでを計る
- AIの出力は、加工せずにそのまま記録する
- 確認ポイントの原文の抜き出しが、`document.txt` と一字一句一致するかを確かめる（テキストエディタの検索で確かめられる）

## 記録の方法

1. [results/TEMPLATE.md](results/TEMPLATE.md) を複製し、`results/YYYY-MM-DD_<モデル>_<ケース>_<条件>.md` という名前で保存する（例：`2026-10-20_gpt-4.1_04-disclaimer_A.md`）
2. AIの出力を貼り、`expected.md` と比べて採点する
3. 全体の結果を、[../README.md](../README.md) の「動作確認モデルと評価」に要約する

## まだ足りないケース

- **長い規約**：数十条の利用規約。後半の条項の抜けと、分割して送る方法を確かめる
- **プライバシーポリシーとの組み合わせ**：利用規約から「個人情報はプライバシーポリシーによる」と参照されている場合
- **改定のお知らせ**：新旧の規約を比べて、変わった点を示せるか（ガイドラインの05-revisionに近い）
