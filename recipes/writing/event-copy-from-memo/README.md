# 設計と検証：地域イベントのチラシ・SNS文章を作る

技術者・改善に参加したい人向けの文書。プロンプトがなぜこの形になっているのか、苦手なケース、評価方法を説明する。

利用者向けの使い方はWebサイトに表示する。その素材は [page.md](page.md)（カード・使い方・注意）と [prompts/](prompts/)（コピー用プロンプト）にある。

## 1. 設計目標

> **地域団体・自治会・子ども会などでイベントを担当する人が、GPT-4.1でも、イベントのメモから、地域の人が「少し行ってみたい」と思えるキャッチコピー・チラシの紹介文・SNSの紹介文を、事実を作らずに短時間で作れること。**

「文章作成」カテゴリの2本目のRecipe。[メモからお知らせ文を作る](../notice-from-memo/) と同じく行事のメモを入力にするが、目的が違う。

| | お知らせ文 | このRecipe |
|---|---|---|
| 目的 | 読み手が迷わず行動できる | 読み手が行ってみたいと思える |
| 文体 | 事務的・簡潔 | 明るく親しみやすい |
| 成果物 | タイトル・本文・要点・件名 | キャッチコピー・チラシの紹介文・基本情報・SNSの紹介文 |
| 特有の失敗 | 締切や連絡先を作る | 魅力や条件（無料、新鮮、誰でも参加可能）を作る、誇張する |

チラシの画像を作るRecipe（作成予定）の前段として使えるよう、STEP 3の出力に「チラシに載せる基本情報」を独立した一覧で含める。

## 2. この仕事の分解

「このイベントのチラシ文を作って」という短い指示の裏で、AIは次の仕事を同時に求められている。

1. どのようなイベントで、誰に来てほしいのかを把握する
2. メモの情報を、基本情報・対象・内容・参加方法などに振り分ける
3. 参加する人が行動するのに足りない情報、食い違う情報に気づく
4. 魅力を、メモにある事実だけから引き出す
5. 媒体（チラシ、SNS）ごとに、長さと構成を変えて書く
6. 対象に合った、明るく親しみやすい言葉を選ぶ

一度に求めると、3と4が崩れやすい。広報文は「楽しそうに書く」ことが求められるため、お知らせ文よりもさらに、メモにない魅力（「新鮮な」「大人気の」）や条件（「参加無料」「どなたでも」）を付け加えやすい。そこで他のRecipeと同じく、STEP 1で事実の整理と点検を行い、STEP 3で編集する。

```text
イベントのメモ
    ↓
STEP 1　把握 → 抽出 → 項目の整理（記載あり／未定／不足／矛盾）（＋必要な場合だけ質問）
    ↓
STEP 2　利用者が不足を補い、入れたい表現・媒体・ハッシュタグの希望を伝える
    ↓
STEP 3　整理した情報だけで、キャッチコピー・チラシ・SNSに編集（＋セルフチェック）
```

### 元の案からの変更

このRecipeは、利用者が約35項目の入力欄（基本情報・対象・内容・参加方法・伝えたいこと・掲載条件）を埋めてから、1回で情報確認と文章作成を行うプロンプトとして提案された。入力欄の項目、禁止事項、文字数、出力の構成はその案を引き継ぎ、次の点を変えた。

| 元の案 | 変更 | 理由 |
|---|---|---|
| 利用者が入力欄を埋める | メモを貼り、AIが項目に振り分ける。入力欄は「書くとよいこと」として `page.md` に短く示す | 利用者の操作を「貼る・答える」に保つ（[design-principles.md](../../../docs/design-principles.md) の原則3）。空欄の多いテンプレートは、初心者には埋める負担が大きい |
| 1回で情報確認と文章作成を行い、不足があっても仮案を作る | STEP 1で整理と質問、STEP 3で文章作成 | 不足を確認する前に文章を作ると、仮案に推測が混ざりやすく、利用者も仮案のまま使いやすい |
| 「地域の親子が読みやすい」と対象を固定 | STEP 1で整理した主な対象に合わせる（親子・一般・高齢の方） | 地域イベントには、親子向け以外（高齢の方向け、大人向け）もある |
| セルフチェックで文字数を確認する | 文字数は目安として指示し、確認は人間が行う（`page.md` の「最後に確認すること」） | GPT-4.1を含む多くのモデルは日本語の文字数を正確に数えられない。「収まっている」と自己申告させると、確認したように見えてしまう |
| ―（記載なし） | 曜日を付け加えない | 曜日の誤りは案内文で最も多い誤りの1つ（[notice-from-memo](../notice-from-memo/) の3章） |
| 紹介文の中に日時・会場・参加費を入れる | 紹介文とは別に「チラシに載せる基本情報」を一覧で出す | チラシでは基本情報を別枠に置くことが多い。一覧にするとメモとの照合がしやすく、チラシ画像のRecipeにもそのまま渡せる |

## 3. 判断基準

### 項目の状態

| 状態 | 意味 | STEP 3での扱い |
|---|---|---|
| 記載あり | メモに書かれている | メモの表記のまま使う |
| 未定 | メモに「未定」と書かれている | 利用者が答えれば使う。答えがなければ【要確認：○○】 |
| 不足 | 参加する人が行動するのに必要だが、メモにない | 同上 |
| 矛盾 | メモの中で食い違っている | どちらかに決めず質問する。答えがなければ【要確認】 |

「未定」を「不足」と分けたのは、元の案の「『未定』『不明』の場合は勝手に補わず『要確認』」を引き継ぐためである。未定の項目は、作成者が把握しているが決まっていないもので、質問しても答えが出ないことが多い。

### 魅力として使ってよいもの

| メモの例 | 正しい扱い | よくある誤り |
|---|---|---|
| 「地元の農家さんの野菜を販売」 | 「地元の農家さんの野菜」と書く | 「新鮮な」「とれたての」を付ける |
| 参加費の記載なし | 不足として質問。答えがなければ【要確認：参加費】 | 「参加無料」と書く |
| 「小学生向けの工作コーナー」 | 小学生向けと書く | 「お子さまからご年配の方まで、どなたでも」と広げる |
| 「昨年は200人が参加」 | 実績として使ってよい | ― |
| 実績の記載なし | 書かない | 「毎年大人気」「多くの方が参加」 |
| 「先着30名」 | 条件として保持 | 「お見逃しなく」「今すぐ申込を」と急かす |

## 4. 中間フォーマット

STEP 1では次の「箱」に整理させる。

- イベントの概要（どのようなイベントか、主な対象）
- 項目の整理の表（項目・メモの記載・状態）
- 確認したいこと（＋入れたい表現・媒体・ハッシュタグの希望を書くよう促す1行）

STEP 3では、この表を唯一の根拠にして、キャッチコピー・チラシの紹介文・チラシに載せる基本情報・SNSの紹介文を作る。

## 5. 人間への確認

| 質問する場面 | 理由 |
|---|---|
| 開催日・時間・会場・参加費・申込方法・問い合わせ先が不足・矛盾している | 案内文として機能しない。参加費は、ないと「無料」と補われやすい |
| 主な対象が分からない | 親子向けと高齢の方向けでは、言葉づかいが大きく変わる |

入れたい表現・避けたい表現・SNSの媒体・ハッシュタグは、質問として数えず、STEP 1の最後の1行で「希望があれば書く」よう促すだけにした。元の案ではすべて入力欄だったが、多くの利用者には希望がなく、毎回質問すると負担になるため。

選択肢には「案内文に書かない」を含める（例：定員を設けない、主催者名を出さない）。

## 6. 使っている設計パターン

共通のパターンは [docs/prompt-patterns.md](../../../docs/prompt-patterns.md) を参照。

| パターン | このRecipeでの使い方 |
|---|---|
| P1 処理の順序を固定する | 把握 → 抽出 → 整理 → 確認 |
| P2 分類は定義で渡す | 項目（基本情報・対象・内容・参加方法・伝えたいこと・掲載条件）と、状態（記載あり・未定・不足・矛盾） |
| P3 禁止事項を具体的に書く | 魅力・条件の付け加え（新鮮、無料、誰でも参加可能）、曜日の計算、誇張・参加を迫る言い方（必ず、限定、お見逃しなく） |
| P4 分からないことの書き方を決める | STEP 1は「未定」「不足」「矛盾」、STEP 3は【要確認：○○】 |
| P5 出力フォーマットを固定する | キャッチコピー3案（おすすめと理由）、紹介文の4段の順序、基本情報の一覧 |
| P6 中間出力を次の入力にする | STEP 1の表を、STEP 3の唯一の根拠にする |
| P7 必要なときだけ質問する | 行動に必要な情報と対象に限定。質問は5つまで |
| P8 確認対象を指定してセルフチェック | 作られた情報・魅力、曜日、キャッチコピーの誤解、【要確認】、次の行動、誇張 |
| P9 入力の区切りと念押し | メモを `↓↓↓` `↑↑↑` で囲み、メモの後で「魅力も推測で補わない」を再確認させる |
| P10 文字数の上限に備える | メモの欄が空のときは待つ指示。`page.md` に、分けて送る方法とメモを短くする方法を載せる |

## 7. 限界と注意点

- メモにない魅力は作らないため、メモが少ないと案内文も淡白になる。魅力を伝えたい場合は、メモに「一番の魅力」を具体的に書く必要がある
- 文字数は目安であり、正確には収まらないことがある。確認は人間が行う
- 曜日の正しさは確認しない
- 写真・出演者名・出店者名・ロゴなどの掲載許可は扱わない
- 景品表示法などに関わる表示（「無料」「割引」）や、食品の販売・提供に関する表示の適否は判断しない
- やさしい日本語や多言語への対応は、このRecipeの範囲外である

### テストケース

架空の団体・地名によるメモを使う。テストセット（`evals/`）は未作成。

| ケース | 内容 | 確かめること |
|---|---|---|
| 1. 標準 | 必要な情報がそろった親子向けの秋まつり | 基本動作。情報を落とさず、作らないか |
| 2. 参加費なし | 参加費と申込方法が書かれていない | 「無料」「申込不要」を補わず、質問できるか |
| 3. 魅力の誘惑 | 野菜の販売、キッチンカー、昨年の参加人数 | 「新鮮」「大人気」を付けず、実績はメモどおりに使うか |
| 4. 未定が多い | 会場と雨天時が「未定」 | 「未定」を【要確認】で残し、確定のように書かないか |
| 5. 高齢の方向け | 健康体操と茶話会 | 親子向けの言葉づかいにならないか |
| 6. 表現の指定 | 入れたい表現・避けたい表現、ハッシュタグなし | 指定に従うか |

### 評価指標

[docs/evaluation.md](../../../docs/evaluation.md) の基本評価項目に加えて、次を記録する。

| 評価項目 | 確認内容 |
|---|---|
| 事実性 | メモと回答にない日時・場所・料金・申込方法・連絡先・曜日を書いていないか |
| 魅力の根拠 | メモにない魅力・条件・実績（新鮮、無料、誰でも、大人気）を付け加えていないか |
| 不足・矛盾・未定の扱い | 質問し、答えのない項目を【要確認】で残せたか |
| 条件の保持 | 雨天時・定員・先着順・対象の条件を残せたか |
| 表現の適切さ | 対象に合った言葉づかいか。誇張や参加を迫る言い方がないか |
| キャッチコピー | 内容を誤解させないか。おすすめの理由が妥当か |
| 文字数 | 目安の範囲から大きく外れていないか（±20%程度を許容） |
