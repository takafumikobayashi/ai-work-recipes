# 評価：メモからお知らせ文を作る

このRecipeを、最低動作モデル（GPT-4.1）で検証するためのテストセットと記録。評価の考え方は [docs/evaluation.md](../../../../docs/evaluation.md)、評価指標は [../README.md](../README.md) の8章を参照。

## テストケース

メモはすべてテスト用に作った**架空のメモ**。「ひかり町」「みどり市」とその団体は実在しない。電話番号は実在しない `000-` で始まる番号、メールアドレスは例示用のドメイン（`example`）を使っている。

| ケース | 内容 | 主に確かめること |
|---|---|---|
| [01-standard](cases/01-standard/) | 自治会の一斉清掃。必要な情報がそろったメモ | 基本動作。情報を落とさず、作らないか |
| [02-missing](cases/02-missing/) | 健康講座。申込締切と電話番号がない | 不足を質問し、答えのない項目を【要確認】で残せるか |
| [03-conditions](cases/03-conditions/) | 防災訓練。受付時刻、保護者同伴、先着、駐車場なし、雨天時の一部中止 | 6つの条件を落とさないか |
| [04-change](cases/04-change/) | 親子料理教室の日程変更 | 変更前と変更後を取り違えないか |
| [05-messy](cases/05-messy/) | 夏まつりの走り書き。開始時刻が食い違い、問い合わせ先は個人の携帯 | 矛盾と不足を質問できるか |
| [06-internal](cases/06-internal/) | 職員向けのシステム停止 | 職員向けの言葉づかいと、期限・代わりの手順を落とさないか |

各ケースのフォルダには、貼り付ける `memo.txt` と、正解とよくある誤りを書いた `expected.md` がある。**実施する前に `expected.md` を見ないこと**。

## STEP 2での答え方

実施する人によって結果が変わらないよう、STEP 2の答え方を決めておく。

| ケース | 答え方 |
|---|---|
| 02-missing | すべての質問に「未定です。そのまま進めてください」と答える |
| 04-change | 読み手を聞かれたら「B」と答える |
| 05-messy | 開始時刻は「まつりの開始は17時30分です」、問い合わせ先は「ひかり町自治会 夏まつり実行委員会 電話 000-444-5555 にしてください」、読み手は「A」と答える |
| その他 | メモから分かる範囲で答える。分からないことは「不明です。そのまま進めてください」と答える |

## 実施条件

| 条件 | 手順 |
|---|---|
| A 通常 | STEP 1のプロンプトのメモ欄に `memo.txt` を貼って送る → 質問があれば答える → STEP 3を送る |
| B 分けて送る | STEP 1のプロンプトをそのまま送る → 「メモを貼り付けてください」と返るか確認 → `memo.txt` を送る → 以降はAと同じ |
| C 一発指示 | 「以下のメモから、お知らせ文を作成してください。」の後に `memo.txt` を貼って送る（比較の基準） |

### 最初に行う組み合わせ（9回）

| ケース | A 通常 | B 分けて送る | C 一発指示 |
|---|:---:|:---:|:---:|
| 01-standard | ✓ | ✓ | |
| 02-missing | ✓ | | ✓ |
| 03-conditions | ✓ | | ✓ |
| 04-change | ✓ | | |
| 05-messy | ✓ | | |
| 06-internal | ✓ | | |

Cの結果は、「メモにない締切や連絡先を作っていないか」（02）と「条件が残っているか」（03）を中心に比べる。このRecipeで手順を分けた効果が最も出やすいのは、02の不足の扱いである。

## 実施のルール

- **1回ごとに新しい会話**を始める
- 使ったサービス名、モデル名、日付を記録する
- 所要時間は、STEP 1のプロンプトをコピーしてから、お知らせ文を受け取るまでを計る
- AIの出力は、加工せずにそのまま記録する

## 記録の方法

1. [results/TEMPLATE.md](results/TEMPLATE.md) を複製し、`results/YYYY-MM-DD_<モデル>_<ケース>_<条件>.md` という名前で保存する（例：`2026-10-20_gpt-4.1_02-missing_A.md`）
2. AIの出力を貼り、`expected.md` と比べて採点する
3. 全体の結果を、[../README.md](../README.md) の「動作確認モデルと評価」に要約する

## まだ足りないケース

- **住民向けで、むずかしい用語が多いメモ**：制度の名前や略語（「マイナ」「特定健診」など）が多いメモ。やさしい言葉への言い換えと、言い換えで意味が変わらないかを確かめる
- **中止のお知らせ**：中止の理由、払い戻しの方法、代わりの日程がないことなど、変更とは違う項目がそろうか
